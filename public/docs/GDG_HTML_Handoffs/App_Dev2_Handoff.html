2. Global Naming & Data Integration Dictionary

To ensure your mobile app connects perfectly with the Backend (Node.js/Express) developers, you MUST strictly use these exact JSON keys when serializing/deserializing Data Models:

  • Identifiers: Always map userId, taskId, formId correctly in your .fromJson() methods. NEVER use _id directly in UI.
  • Response Format: The backend will always respond with this structure. Ensure your repository layer checks response['success']:
    • Success: { "success": true, "data": { ... } }
    • Error: { "success": false, "message": "error string" }
  • Task Status Enum: Your UI must handle "pending", "in-progress", "in-review", "completed".

3. Feature Breakdown & Widget Logic

Feature 1: Task Management & Calendar (A08 - A13)

Users will navigate between a List view of tasks and a Calendar view.

Required Widgets (screens/ & components/):

  1. TasksScreen (A09) & TaskFilters (A11):
    • Logic: A Scaffold with a TabBar or simple Segmented Control. Uses ListView.builder for displaying Task Cards.
    • Filters: Provide a BottomSheet containing DropdownButtonFormField for filtering by status and priority.
    • API Connection: GET /api/tasks?status=....
  2. CalendarScreen (A08):
    • Logic: Use a package like table_calendar. Map the dueDate of tasks as markers on the calendar. Tapping a day shows the list of tasks for that day below the calendar grid.
  3. AddTaskSheet (A10):
    • Logic: A modal bottom sheet (or separate screen) to create a new task.
    • Form Fields: Title (TextFormField), Description, Assignee (Searchable Dropdown fetched from /api/users/directory), Due Date (showDatePicker), and Priority.
    • API Connection: Submits POST /api/tasks.
  4. TaskWorkflowView (A12) & ActivityLog (A13):
    • Logic: The details screen for a specific task. Includes prominent Action Buttons ("Start Work", "Submit").
    • Activity Log: A ListView at the bottom of the details screen showing chronological status updates.

Example Provider State (providers/tasks_provider.dart):

import 'package:flutter/material.dart';
import '../data/repository/tasks_repository.dart';

class TasksProvider extends ChangeNotifier {
  final TasksRepository _repository = TasksRepository();
  List<dynamic> tasks = [];
  bool isLoading = false;

  Future<void> fetchTasks({String status = 'all'}) async {
    isLoading = true;
    notifyListeners();

    try {
      final response = await _repository.getTasks(status);
      if (response['success']) {
        tasks = response['data'];
      }
    } catch (e) {
      print("Failed to fetch tasks");
    } finally {
      isLoading = false;
      notifyListeners();
    }
  }
}

Feature 2: Dynamic Forms (A23 - A26)

This module allows users to see forms created by Admins and submit responses dynamically from their phones.

Required Widgets (screens/FormsScreen.dart & components/):

  1. ActiveFormsGrid (A23):
    • Logic: A GridView displaying available forms.
    • API Connection: GET /api/forms/active.
  2. FormInstructionsSheet (A25):
    • Logic: A bottom sheet showing markdown/rich-text rules before the user starts the form. Use the flutter_markdown package.
  3. DynamicFieldsList (A24):
    • Logic: Extremely important component. It receives a JSON array of fields from the backend (e.g., [{ "type": "text", "label": "Name" }, { "type": "dropdown", "options": ["A", "B"] }]).
    • Rendering: Write a switch statement that iterates over the JSON array and returns the corresponding Flutter widgets (TextFormField, DropdownButtonFormField, etc.).
    • State: Maintain a Map<String, dynamic> responses in your Provider to hold the user's input.
    • API Connection: Submits POST /api/forms/:formId/submit.

4. Cross-Team Integration Points (Crucial)

As a Mobile Frontend Developer, you need to use utilities built by others. Follow these strict rules to avoid bugs:

1. Global API Client (core/network/api_client.dart)

  • Do NOT write raw http.get calls containing Authorization: Bearer <token> in your repository files.
  • The project architect will create a shared Dio instance in the lib/core/ folder containing an Interceptor that automatically attaches the JWT token.
  • You must import and use this Dio client in your data/repository/ folders.

2. Global State (Authentication)

  • To get the current user's ID (e.g., to default assign a task to yourself), use the global AuthProvider.
    final user = Provider.of<AuthProvider>(context, listen: false).currentUser;

3. Shared UI Components

  • Use standard UI elements from the lib/shared/widgets/ library so that your module matches the material styling of the rest of the application perfectly. Do not hardcode raw hex colors; use Theme.of(context).colorScheme.
