2. Global Naming & Data Integration Dictionary

To ensure your mobile app connects perfectly with the Backend (Node.js/Express) developers, you MUST strictly use these exact JSON keys when serializing/deserializing Data Models:

  • Identifiers: Always map userId, taskId, meetingId correctly in your .fromJson() methods. NEVER use _id directly in UI.
  • Response Format: The backend will always respond with this structure. Ensure your repository layer checks response['success']:
    • Success: { "success": true, "data": { ... } }
    • Error: { "success": false, "message": "error string" }

3. Feature Breakdown & Widget Logic

Feature 1: Main Dashboard (A01 - A07)

The Dashboard is the first screen the user sees after logging in. It's a ScrollView aggregating data from multiple APIs.

Required Widgets (screens/DashboardScreen.dart & widgets/):

  1. WelcomeHeader (A01):
    • Logic: Reads user.name from the global auth provider to display a greeting.
  2. StatsGrid (A02):
    • Logic: A GridView displaying 4 summary cards.
    • Data Source: Calls DashboardRepository.fetchStats() which hits GET /api/users/me/stats.
  3. NextMeetingCard (A03):
    • Logic: Highlights the upcoming meeting. Includes an ElevatedButton "Join Now" that deep links to the Meeting Screen.
  4. MyTasksList (A04):
    • Logic: A condensed ListView.builder showing the top 3 high-priority tasks.
  5. FloatingQuickActions (A05):
    • Logic: A custom FloatingActionButton or a row of circular icon buttons for rapid actions: "Apply Leave", "Create Task". These should open Bottom Sheets (showModalBottomSheet).
  6. UpdatesGraph (A06):
    • Logic: Use a package like fl_chart to render a line/bar chart showing team activity.
  7. GlobalSearch (A07):
    • Logic: A TextField at the top of the AppBar. Should use a Debouncer (300ms) before triggering GET /api/users/directory?search=....

Example Provider State (providers/dashboard_provider.dart):

import 'package:flutter/material.dart';
import '../data/repository/dashboard_repository.dart';

class DashboardProvider extends ChangeNotifier {
  final DashboardRepository _repository = DashboardRepository();
  
  Map<String, dynamic>? stats;
  bool isLoading = false;
  String? errorMessage;

  Future<void> loadDashboardData() async {
    isLoading = true;
    notifyListeners();

    try {
      final response = await _repository.fetchStats();
      if (response['success'] == true) {
        stats = response['data'];
      } else {
        errorMessage = response['message'];
      }
    } catch (e) {
      errorMessage = "Network error occurred.";
    } finally {
      isLoading = false;
      notifyListeners();
    }
  }
}

4. Cross-Team Integration Points (Crucial)

As a Mobile Frontend Developer, you need to use utilities built by others. Follow these strict rules to avoid bugs:

1. Global API Client (core/network/api_client.dart)

  • Do NOT write raw http.get calls containing Authorization: Bearer <token> in your repository files.
  • The project architect will create a shared Dio instance in the lib/core/ folder containing an Interceptor that automatically attaches the JWT token.
  • You must import and use this Dio client in your data/repository/ folders.

2. Global State (Authentication)

  • You do not need to write the Login Screen (App Dev 3 is doing that).
  • However, your Dashboard needs to know who is logged in. You will consume the global AuthProvider to get the user's data.
    final user = Provider.of<AuthProvider>(context, listen: false).currentUser;
