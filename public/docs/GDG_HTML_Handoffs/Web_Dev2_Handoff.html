2. Global Naming & Data Integration Dictionary

To ensure your frontend connects perfectly with the Backend (Node.js/Express) developers, you MUST strictly use these exact JSON keys:

  • Identifiers: Always use userId, taskId, meetingId. NEVER use _id directly in components without mapping it.
  • API Response Format: You must check response.success before using data:
    • Success: { "success": true, "data": { ... } }
    • Error: { "success": false, "message": "error string" }
  • Task Status Enum: "pending", "in-progress", "in-review", "completed".

3. Feature Breakdown & Component Logic

Feature 1: Task Management & Calendar (W08 - W13)

This is the most complex part of your module. Users will switch between a List/Kanban view and a Calendar view.

Required Components (tasks/components/):

  1. ViewToggle.jsx:
    • Logic: A simple tab or segmented control to switch the local state between 'list' and 'calendar' views.
  2. TasksListView.jsx (W09) & TaskFilters.jsx (W11):
    • Logic: A Data Table or Kanban board showing tasks.
    • Filters: Must include dropdowns to filter by status (pending, completed) and priority (low, urgent).
    • Data Source: Calls GET /api/tasks?status=... (Backend Dev 2).
  3. CalendarView.jsx (W08):
    • Logic: You can use a library like react-big-calendar or fullcalendar. It should map the dueDate of tasks onto the grid. Clicking a date/event opens the task details modal.
  4. AddTaskModal.jsx (W10):
    • Logic: A form to create a new task. Requires title, description, assignedTo (fetch list of users from GET /api/users/directory), dueDate, and priority.
    • API Connection: Submits POST /api/tasks.
  5. TaskWorkflowTable.jsx (W12) & ActivityLog.jsx (W13):
    • Logic: When viewing a specific task, show buttons to change its status (e.g., "Start Work", "Submit for Review").
    • Activity Log: A chronological list of status changes fetched from the backend (e.g., "John moved task to In-Review at 10:00 AM").

Example Task State Hook (tasks/hooks/useTasks.js):

import { useState, useEffect } from 'react';
import apiClient from '../../../shared/api/apiClient';

export const useTasks = (filters) => {
    const [tasks, setTasks] = useState([]);
    const [loading, setLoading] = useState(true);

    useEffect(() => {
        const fetchTasks = async () => {
            setLoading(true);
            try {
                // filters is an object like { status: 'pending', priority: 'urgent' }
                const params = new URLSearchParams(filters).toString();
                const response = await apiClient.get(`/api/tasks?${params}`);
                if (response.data.success) {
                    setTasks(response.data.data);
                }
            } catch (err) {
                console.error("Failed to load tasks");
            } finally {
                setLoading(false);
            }
        };
        fetchTasks();
    }, [filters]); // Refetch when filters change

    return { tasks, loading };
};

4. Cross-Team Integration Points (Crucial)

As a Web Frontend Developer, you need to use utilities built by others. Follow these strict rules to avoid bugs:

1. Global API Client (shared/api/apiClient.js)

  • Do NOT write raw fetch() calls containing Authorization: Bearer <token> in every single file.
  • The project architect will create a shared apiClient.js (using Axios) in the shared/ folder. This client will automatically attach the JWT token to every request.
  • You must import and use this client in your api/ folders.

2. State Management & Modals

  • If your AddTaskModal needs to block the entire screen, use the shared <Modal /> component from the shared/components/ folder to ensure the backdrop and z-index are consistent with the rest of the application.
  • To get the current user's ID for assigning tasks, use the global auth hook (e.g., const { user } = useAuthStore()). Do not parse the JWT yourself.
