Technical Specification & Handoff: Backend Developer 3 (Real-time & Analytics)

Developer Profile: Backend Dev 3
Working Directory: backend/src/dev3_realtime_chat/
Core Responsibilities: Real-time Chat (Socket.io), WebSocket Architecture, Chat History APIs, and Complex Analytics Dashboards (MongoDB Aggregation).

Objective: This document provides the complete business logic, API contracts, and database specifications required to build your module. You are responsible for writing the actual implementation code (Node.js/Express/Socket.io).

1. Global Naming & Data Dictionary (Must Follow)

To ensure your WebSockets and APIs connect perfectly with the Web and App teams, you MUST strictly use these exact terms:

  • Identifiers: Always use userId, channelId, messageId. NEVER use user_id or id_channel.
  • JSON Keys: Always use camelCase (e.g., isGroupChat, senderId, readBy).
  • Response Format: Every single REST API response you build MUST be wrapped in:
    • Success: { "success": true, "data": { ...your_data } }
    • Error: { "success": false, "message": "error string" }

2. Database Schema Specifications

You are responsible for creating the Chat and Channel models.

A. Channel Collection (ChannelModel.js)

  • name: String (Only required if it's a group chat).
  • isGroupChat: Boolean, Default: false.
  • members: Array of ObjectIds (Reference to User collection).
  • adminId: ObjectId (If it's a group chat, who created it).
  • lastMessageAt: Date.

B. ChatMessage Collection (ChatModel.js)

  • channelId: ObjectId, Required. Reference to Channel.
  • senderId: ObjectId, Required. Reference to User.
  • content: String, Required.
  • fileUrl: String (Optional, for image/PDF attachments via Cloudinary).
  • readBy: Array of ObjectIds (Users who have seen the message).

3. WebSocket Architecture (Socket.io)

This is the core of your module. You will build a stateful WebSocket server using Socket.io.

A. Socket Initialization & Security

  1. JWT Authentication: You MUST write middleware for Socket.io that extracts the JWT token from the handshake connection. Do not allow unauthorized sockets to connect.
  2. Room Joining: Upon successful connection, immediately join the socket to a private room named after their userId (e.g., socket.join(userId)). This allows private messages and notifications to be routed to them.

B. Socket Event Contracts (WS-01 to WS-04)

You must listen for and emit the following exact event names so the Frontend teams can bind to them.

  1. Event: send_message (Frontend to Backend)
    • Payload: { "channelId": "...", "content": "Hello" }
    • Logic: Save message to DB, update Channel lastMessageAt, and emit receive_message to all other members of the channel.
  2. Event: receive_message (Backend to Frontend)
    • Payload: { "messageId": "...", "channelId": "...", "senderId": "...", "content": "Hello", "createdAt": "..." }
  3. Event: typing and stop_typing
    • Payload: { "channelId": "...", "senderId": "..." }
    • Logic: Broadcast to everyone in the channel EXCEPT the sender.

4. REST APIs & Business Logic

A. Chat APIs (/api/chat)

  • GET /api/chat/channels: Fetch all channels the req.user.userId is a member of, sorted by lastMessageAt descending.
  • GET /api/chat/:channelId/messages: Fetch paginated chat history for a channel.

B. Analytics API (API-19) - (/api/analytics)

  • Endpoint: GET /api/analytics/dashboard-stats
  • Auth Required: Yes (JWT + Admin Role check - attach Dev 4's middleware later).
  • Business Logic Flow:
    • You are responsible for writing complex MongoDB Aggregation Pipelines.
    • You must aggregate data across collections (even collections created by Dev 2 like Tasks and Leaves).
    • Data Required: Total Active Users, Total Tasks Completed this month, Leave Approval Ratio.
    • Performance: Ensure your pipelines use $match early to use indexes.

5. Cross-Team Integration Points (Crucial)

1. Global Socket Accessibility (Interacting with Dev 1)

CRITICAL: Dev 1 (Auth & Users) is building a NotificationService that needs to send real-time alerts. But they do not know how Socket.io works. You MUST attach your initialized Socket.io io instance to the global Node.js object when the server starts, so Dev 1 can access it.

// Inside your socket initialization file (e.g., chat.socket.js)
const { Server } = require('socket.io');

const initSockets = (server) => {
    const io = new Server(server, { cors: { origin: '*' } });
    
    // Attach to global so Dev 1 can do: global.io.to(userId).emit('new_notification', ...)
    global.io = io; 
    
    io.on('connection', (socket) => {
        // ... your chat logic ...
    });
};

module.exports = { initSockets };
