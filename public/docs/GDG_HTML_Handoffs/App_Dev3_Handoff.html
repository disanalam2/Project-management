To ensure your mobile app connects perfectly with the Backend (Node.js/Express) developers, you MUST strictly use these exact JSON keys when serializing/deserializing Data Models:

3. Feature Breakdown & Widget Logic

Feature 1: Global Authentication Flow (A31, A36)

You are responsible for the Login screen and securely storing the JWT token on the mobile device.

Required Widgets (screens/LoginScreen.dart):

  1. LoginForm (A31):
    • Logic: Standard Email/Password login UI.
    • API Connection: Submits POST /api/users/login (Backend Dev 1).
    • Post-Login Storage: On success, extract the token and user object. You MUST save the token securely using flutter_secure_storage (not standard SharedPreferences).
    • State: Update the global AuthProvider and use Navigator.pushReplacementNamed to send the user to the Dashboard (/dashboard).
  2. ForgotPasswordFlow (A36):
    • Logic: A multi-step UI. Step 1: Request OTP. Step 2: Enter OTP. Step 3: New Password.

Example Auth Provider (providers/auth_provider.dart):

import 'package:flutter/material.dart';
import 'package:flutter_secure_storage/flutter_secure_storage.dart';
import '../data/repository/auth_repository.dart';

class AuthProvider extends ChangeNotifier {
  final AuthRepository _repository = AuthRepository();
  final storage = const FlutterSecureStorage();
  
  Map<String, dynamic>? currentUser;
  String? token;

  Future<bool> login(String email, String password) async {
    final response = await _repository.login(email, password);
    if (response['success']) {
      token = response['data']['token'];
      currentUser = response['data']['user'];
      await storage.write(key: 'jwt_token', value: token);
      notifyListeners();
      return true;
    }
    return false;
  }
}

4. Cross-Team Integration Points (Crucial)

As a Mobile Frontend Developer, you need to use utilities built by others. Follow these strict rules to avoid bugs:

1. The Global Auth Provider

  • You are building the AuthProvider. Ensure it is robust, bug-free, and handles auto-login on app startup (by checking flutter_secure_storage for an existing token). Other developers will rely entirely on this to get the user's ID and role.

2. Global API Client (core/network/api_client.dart)

  • The project architect will create a shared Dio instance in the lib/core/ folder. This client will automatically read the token you saved in Secure Storage and attach it as a Bearer token to all requests.
  • You must import and use this Dio client in your data/repository/ folders. Do not use raw http.get.

3. Shared UI Components

  • Use standard UI elements from the lib/shared/widgets/ library so that your module matches the Material 3 styling of the rest of the application perfectly.
