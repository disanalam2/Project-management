3. Feature Breakdown & Component Logic

Feature 1: Master Admin Dashboard & IAM (W37 - W41)

This module allows root admins to control the entire application.

Required Components (admin/components/):

  1. AdminStatsOverview.jsx (W37):
    • Logic: High-level metrics for the Admin (Total Users, Active Sessions, System Errors).
  2. MemberManagementTable.jsx (W38):
    • Logic: A powerful data table listing all registered users. Admins can click a user to edit their profile, suspend them, or change their role.
    • API Connection: PUT /api/users/:userId/status (Backend Dev 1).
  3. RoleIAMEditor.jsx (W40):
    • Logic: The Identity and Access Management UI. Admins can create new Roles (e.g., "Manager") and toggle specific permissions on/off using checkboxes (e.g., canCreateTasks: true, canDeleteMeetings: false).
    • API Connection: POST /api/iam/roles and PUT /api/iam/roles/:roleId (Backend Dev 4).
  4. PendingApprovals.jsx (W39):
    • Logic: A queue showing users waiting for account verification. Admins can hit "Approve" or "Reject".
  5. BulkUploadZone.jsx (W41):
    • Logic: A drag-and-drop file uploader that accepts .csv files to bulk-create hundreds of user accounts at once.
    • API Connection: Submits POST /api/users/bulk-upload (multipart/form-data).

Feature 2: Real-Time Chat App (W42 - W43)

A full-fledged internal messaging system similar to Slack or Discord.

Required Components (chat/components/):

  1. ChatSidebar.jsx:
    • Logic: Lists available "Channels" (e.g., #general, #design) and Direct Messages. Displays unread message badges.
  2. ChatWindow.jsx (W42):
    • Logic: The main message area. Must scroll to the bottom on a new message.
    • Real-Time Logic: Uses Socket.io-client. On mount, fetch historical messages via REST (GET /api/chat/channels/:channelId/messages). Then, listen to the socket event receive_message to append new messages dynamically.
  3. MessageInput.jsx (W43):
    • Logic: A text input area. Hitting Enter emits a send_message socket event. Should support uploading images/files (using a paperclip icon).
  4. TypingIndicator.jsx:
    • Logic: Listens for user_typing socket events and displays "John is typing...".

Example Socket Hook (chat/hooks/useChatSocket.js):

import { useEffect, useState } from 'react';
import { io } from 'socket.io-client';
// You will get the global token from the auth store created by Dev 4
import { useAuthStore } from '../../../shared/store/useAuthStore'; 

export const useChatSocket = (channelId) => {
    const { token } = useAuthStore();
    const [messages, setMessages] = useState([]);
    const [socket, setSocket] = useState(null);

    useEffect(() => {
        // Initialize Socket
        const newSocket = io(process.env.NEXT_PUBLIC_SOCKET_URL, {
            auth: { token }
        });
        
        newSocket.on('connect', () => {
            newSocket.emit('join_channel', { channelId });
        });

        newSocket.on('receive_message', (msg) => {
            setMessages((prev) => [...prev, msg]);
        });

        setSocket(newSocket);

        return () => newSocket.close();
    }, [channelId, token]);

    const sendMessage = (text) => {
        socket?.emit('send_message', { channelId, text });
    };

    return { messages, setMessages, sendMessage };
};

4. Cross-Team Integration Points (Crucial)

As a Web Frontend Developer, you need to use utilities built by others. Follow these strict rules to avoid bugs:

1. Global API Client (shared/api/apiClient.js)

  • Do NOT write raw fetch() calls containing Authorization: Bearer <token> in every single file.
  • The project architect will create a shared apiClient.js (using Axios) in the shared/ folder. This client will automatically attach the JWT token to every request.

2. Admin Route Protection

  • Your Admin Dashboard MUST be protected. You must verify the user's role via the global auth store (useAuthStore) before rendering the Admin UI. If a normal user tries to access /admin, redirect them to /dashboard.
