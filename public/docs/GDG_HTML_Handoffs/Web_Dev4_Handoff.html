Technical Specification & Handoff: Web Frontend Developer 4 (Profile, Auth & Settings)

Developer Profile: Web Dev 4
Working Directory: web/src/app/dev4_profile_auth/
Core Responsibilities: Global Authentication Flow, User Profile Settings, System Theming (Dark/Light), Notifications Panel, and Team Directory. Tech Stack: Next.js (App Router), React.js (JavaScript / .jsx), Vanilla CSS/Tailwind.

Objective: This document provides the complete UI architecture, state management logic, component breakdown, and API integration contracts required to build your module. You are responsible for writing the actual implementation code. You hold a crucial role because the Global Authentication state you build will be used by every other frontend developer.

2. Global Naming & Data Integration Dictionary

To ensure your frontend connects perfectly with the Backend (Node.js/Express) developers, you MUST strictly use these exact JSON keys:

  • Identifiers: Always use userId, roleId. NEVER use _id directly in components without mapping it.
  • API Response Format: You must check response.success before using data:
    • Success: { "success": true, "data": { ... } }
    • Error: { "success": false, "message": "error string" }

3. Feature Breakdown & Component Logic

Feature 1: Global Authentication Flow (W31, W36)

You are responsible for the Login screen and securely storing the JWT token.

Required Components (auth/components/):

  1. LoginForm.jsx (W31):
    • Logic: Standard Email/Password login form.
    • API Connection: Submits POST /api/users/login (Backend Dev 1).
    • Post-Login: On success, extract the token and user object from the response. Save the token securely (e.g., in a secure cookie or local storage) and update the global Zustand/Context auth store. Finally, redirect to the Dashboard (/dashboard).
  2. ForgotPasswordModal.jsx (W36):
    • Logic: Two-step flow. Step 1: Request OTP via email. Step 2: Verify OTP and set new password.
    • API Connection: POST /api/users/forgot-password and POST /api/users/reset-password.

Feature 2: User Profile & Settings (W27 - W30)

This module allows users to configure their app experience.

Required Components (profile/components/):

  1. UserProfileForm.jsx (W27):
    • Logic: A form to view and edit personal details (Name, Phone, Bio, Profile Picture).
    • API Connection: Calls GET /api/users/me and PUT /api/users/me.
  2. SidebarNavigation.jsx (W28):
    • Logic: You will build the global sidebar navigation shell. The routing links will point to URLs handled by other devs (e.g., /tasks, /meetings).
  3. ThemeToggle.jsx (W29):
    • Logic: A switch to toggle between Dark Mode and Light Mode. This should append a dark class to the HTML <body> and save the preference in localStorage.
  4. DevModeSwitch.jsx (W30):
    • Logic: A special toggle that reveals extra debugging information on the screen (only visible to Admins/Developers).

Feature 3: Communications & Misc (W33 - W35)

General community features.

Required Components (communications_misc/components/):

  1. NotificationBell.jsx & NotificationDropdown.jsx (W34):
    • Logic: A bell icon in the top Navbar. Shows an unread count badge. Clicking it opens a dropdown showing recent notifications.
    • API Connection: Calls GET /api/notifications (Backend Dev 4). Must support marking notifications as "read".
  2. TeamDirectory.jsx (W35):
    • Logic: A grid of user cards showing everyone in the organization.
    • API Connection: GET /api/users/directory. Should include search and filter-by-department functionality.
  3. TermsModal.jsx (W33):
    • Logic: A simple static modal displaying Terms and Conditions.

4. Cross-Team Integration Points (Crucial)

As a Web Frontend Developer, you need to use utilities built by others. Follow these strict rules to avoid bugs:

1. Global State Management (Zustand or Context)

  • You must create the useAuthStore.js (in the shared/store/ folder) which holds the user and token.
  • Other developers will rely heavily on your store to know who is logged in. Ensure it is bug-free and persists state across page reloads (using zustand/middleware/persist or similar).

2. Global API Client (shared/api/apiClient.js)

  • The project architect will create a shared apiClient.js (using Axios) in the shared/ folder. This client will automatically attach the JWT token (that YOU saved) to every request.
  • You must import and use this client in your api/ folders.
